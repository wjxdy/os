# 操作系统基础认知文档设计

- 日期：2026-07-21
- 状态：书面设计已通过（2026-07-22）
- 文档类型：面向初学者的 Obsidian 学习文档

## 1. 背景

原阶段 0 课程过早进入 Cargo workspace、toolchain、target 和裸机编译配置。学习者尚未建立这些工具所服务的操作系统心智模型，因此注意力被配置语法和专业词汇消耗，影响理解与学习热情。

课程立即暂停配置驱动的执行顺序。下一步先建立“操作系统由哪些部件组成、各部件为何存在、一次程序执行如何穿过这些部件”的基础认知，再决定何时恢复 Rust 实验和裸机配置。

## 2. 目标与成功标准

创建一篇通俗、完整但不百科化的基础认知地图。阅读后，学习者应能：

1. 用自己的话解释操作系统是资源管理者和隔离边界。
2. 区分程序、进程、操作系统线程、Tokio Task 和 Future。
3. 追踪一次 `println!("hello")` 从应用代码到系统调用、内核和设备输出的路径。
4. 追踪一次 Tokio 网络请求从 Task、Worker Thread、系统调用、内核网络栈到网卡驱动的路径。
5. 说出 CPU 特权级、系统调用、中断、调度、虚拟内存、文件描述符、VFS、驱动、IPC 和同步机制分别解决什么问题。
6. 理解 `no_std`、`unsafe`、ABI、linker 和 bootloader 为什么会在 Rust 内核项目中出现，而不是只记住配置写法。
7. 看见后续课程中的专业词汇时，能够把它放回完整系统地图，而不是孤立记忆。

## 4. 写作方式

采用“分层地图 + 运行故事 + 组件卡片”的混合结构：

- 分层地图先回答“整台系统有哪些层”。
- 运行故事回答“这些层如何在一次真实操作中协作”。
- 组件卡片逐个回答“它是什么、为什么存在、如何工作”。
- 专业术语首次出现时立即用普通语言解释，随后才使用术语简称。
- 先给可工作的粗略心智模型，再补充准确边界；不一开始堆硬件细节。
- 类比只用于入门，并明确指出类比在哪些地方会失效。

文档提供两条阅读路线：

- 快速路线：阅读总地图、两个运行故事和核心组件摘要，约 20 至 30 分钟。
- 完整路线：依次阅读全部组件卡片和术语表，约 60 至 90 分钟。

## 5. 固定组件卡片模板

每个核心组件统一回答：

0. 30 秒结论：只读这一段应该记住什么？
1. 它是什么？
2. 为什么需要它？如果没有会怎样？
3. 它如何工作？
4. 可以用什么生活经验或网络服务经验类比？
5. 类比在哪一点开始不准确？
6. 用 Rust 写内核时会在哪里遇到它？
7. 最容易混淆的概念是什么？

组件说明以“有用的认知”为目标，不展开到寄存器位、协议字段或具体实现代码。

完整组件卡片只用于以下 15 组主题，避免每个术语都扩成独立章节：

1. CPU、寄存器与特权级。
2. 程序、进程、线程、Future 与 Task。
3. 调度器、上下文切换、阻塞与唤醒。
4. 用户态、内核态与系统调用。
5. 中断、异常、时钟与页错误。
6. 物理内存、虚拟内存、页与页表。
7. 栈、堆与分配器。
8. 文件、文件描述符与 VFS。
9. 设备、驱动与 I/O。
10. Socket、内核网络栈与网卡。
11. 竞态、锁、原子操作与临界区。
12. IPC、管道、消息与共享内存。
13. `init`、shell、系统服务与应用。
14. 固件、bootloader 与内核启动。
15. `no_std`、`unsafe`、ABI、ELF、linker 与 cross compilation。

快速路线只阅读每张卡片的“30 秒结论”；完整路线再阅读其余问题。

## 6. 内容结构

### 6.1 总地图

- 操作系统的两个核心职责：资源管理与隔离。
- 应用、用户态运行库、系统调用、内核、驱动、硬件的分层图。
- “内核不等于完整操作系统”“Linux 不等于所有用户空间”的区别。

### 6.2 启动故事

- 上电、固件、bootloader、内核入口、初始化、`init`/第一个用户进程。
- 解释为什么普通 Rust `main` 不能直接成为裸机内核入口。

### 6.3 执行与调度

- CPU、指令、寄存器和特权级。
- 程序、进程、线程、Future、Tokio Task、Worker Thread。
- 调度器、时间片、阻塞、唤醒、上下文切换。
- 使用既有文档 [[Tokio 中的 Task、Future 与线程]] 连接用户态运行时调度与内核线程调度。

### 6.4 内核入口与异步事件

- 用户态与内核态。
- 系统调用。
- 中断、异常、时钟和页错误。
- 对比“程序主动发起系统调用”和“硬件/CPU 主动打断执行”。

### 6.5 内存

- 物理内存、虚拟地址、页、页表和地址空间。
- 栈、堆、内核堆和分配器。
- 进程隔离、非法访问和页错误。
- Rust 所有权解决的语言级问题与页表解决的硬件级问题不能混为一谈。

### 6.6 文件与设备

- 文件、目录、文件描述符和 VFS。
- 设备、设备驱动、块设备与字符设备。
- 缓冲、阻塞 I/O 和异步 I/O。
- `println!("hello")` 的完整路径故事。

### 6.7 网络

- Socket、文件描述符、系统调用、内核网络栈、网卡驱动和中断。
- Tokio Task 等待网络 I/O 时，运行时、线程和内核分别做什么。
- 从学习者熟悉的网络服务开发反向连接到 OS 机制。

### 6.8 并发与通信

- 竞态条件、临界区、锁、原子操作和中断屏蔽。
- IPC、管道、消息传递、共享内存。
- “线程安全”在用户程序与内核中的共同点和额外风险。

### 6.9 用户空间与系统组成

- `init`、shell、系统服务、运行库和普通应用。
- 内核、发行版、桌面环境和完整操作系统的区别。
- AI runtime 为什么应首先作为受限制的用户态服务。

### 6.10 Rust 内核词汇桥梁

- `no_std`：没有现成操作系统服务时为何不能依赖 `std`。
- `unsafe`：硬件边界与语言无法证明的不变量。
- ABI：不同代码如何约定参数、返回值和布局。
- linker 与 ELF：代码如何组成可加载映像。
- bootloader：如何把机器带到可以进入内核的状态。
- Cargo target 与 cross compilation：宿主工具链如何生成另一架构的裸机代码。

### 6.11 推荐实现顺序与术语表

- 从串口输出、异常、内存、任务、用户态、系统调用、文件系统到 shell 的顺序。
- 每一步说明依赖哪些前置概念。
- 术语表提供“一句话解释、所属层、常见混淆对象”。
- 文末提供自测题，重点要求追踪路径和比较概念，不考死记定义。

## 8. 类比策略

优先使用学习者已有经验：

- Tokio runtime 与 OS scheduler：都是调度者，但调度对象、权限和可见资源不同。
- Tokio Task 与 OS thread：Task 是用户态可暂停计算，thread 是内核调度的执行上下文。
- 网络 Socket 与文件描述符：应用看到句柄，内核维护真实对象和状态。
- 线程池与 CPU 核心：工人数量不等于任务数量。
- 系统调用与服务柜台：请求必须从受控入口进入，但真实系统调用包含特权级和安全检查。
- 虚拟内存与独立房间编号：每个进程看到自己的地址布局，但底层映射可以不同。

每个类比必须紧跟一条“类比边界”，避免形成错误模型。

## 9. 非目标

本文不：

- 教用户填写 Cargo、rustup、bootloader 或 QEMU 配置。
- 提供可复制的内核实现代码。
- 深入多核缓存一致性、NUMA、TCP 拥塞控制、图形栈、USB 或具体磁盘格式。
- 追求覆盖所有现实操作系统子系统。
- 把 Linux 的具体实现当作所有操作系统的唯一路线。

覆盖范围限定为“理解并开始实现教学型 Rust 类 Unix 内核所需的组件意识”。

## 11. 课程衔接
